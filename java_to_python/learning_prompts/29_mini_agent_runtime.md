数据与边界：

- 明确 UserRequest、ToolCall、ToolResult、AgentEvent、RunState 的用途；外部输入用 Pydantic 验证，内部状态按实际需要选择 dataclass。
- ToolCall 包含稳定的 call_id、工具名和参数；并发完成顺序改变时，结果仍能准确匹配原调用。
- 通过装饰器注册少量明确工具，拒绝未知工具和不合法参数；不执行任意生成的 Python 代码。
- 用协议表达模型适配器和必要的工具依赖，避免把 SDK 对象散落在整个运行循环里。

运行主线：

用户输入 → 模型给出工具请求 → 校验 → 执行独立工具 → 将结果反馈给模型 → 最终回答。

- 使用可控 FakeLLM 按预设步骤返回工具调用与最终答案；清楚说明这是模型替身，不能据此证明真实推理质量。
- 默认至少 3 个工具：本地文档检索、本地 HTTP 状态查询、临时 SQLite 记录查询；全部本机可运行。
- 只并发调度相互独立的调用；有依赖的下一轮工具等待前一轮结果，不把所有 tool call 都盲目并行。
- 提供明确的 fail-fast 与允许部分业务失败的策略，统一错误结果结构，同时保留取消与未知程序异常。
- 有整体截止时间、单工具预算、并发上限和最大模型调用轮数；重试不额外获得无限预算。
- 同时提供最终结果与 async iterator 事件流，能显示 tool-start、tool-result 和结束状态；提前停止消费时清理执行中的工作。
- 谁拥有 HTTP 客户端、会话、TaskGroup 和事件生成器必须明确；ContextVar 用于运行日志标识。
