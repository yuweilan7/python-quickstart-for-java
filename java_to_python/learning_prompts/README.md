# Python 基础之后：Agent 开发学习路线与逐章 Prompt

这里规划了 20 个部分，对应未来的第 11～30 章。目标是从“能写 Python”走到“能读懂 Agent 框架，并处理真实工具调用的并发、失败与资源生命周期”。

当前交付的是路线和生成课程用的 prompt。第 11～30 章的教程与代码将在后续对话中逐章创建；本目录中的文件本身不代表相应课程已经实现。

## 怎样使用

1. 在下面的目录中打开要学的一章。
2. 复制文件全文，从第一行 `$python-learning-explainer` 开始，粘贴到这个仓库的新对话。
3. 该 prompt 会要求模型读取必要的项目上下文，并在对应的 `java_to_python/chapters/编号_主题/` 中创建 README.md、example.py 及必要辅助文件。
4. 阅读讲解、预测实验结果、运行代码，再完成练习。遇到不理解的运行过程，在该章对话中继续追问。

**每份 prompt 都能独立复制。** 学习背景、Python 版本校验、教学方式、输出路径和验证要求已经放进每份文件，不需要另外拼接一段“公共提示词”。独立复制不等于没有知识前置：每份文件也说明了应该先会什么。

如果只想先学而暂时不写文件，可以在复制后追加：“本次仅在回复中教学，暂不创建或修改文件。”当前对话的明确要求优先于 prompt 中的默认交付方式。

## 为什么这样排

前 10 章已经覆盖容器、函数、对象、模块，以及 JSON 解析、业务校验与 with 文件管理。第 11～12 章因此集中于解释器与依赖的工程关系、HTTP 请求和外部数据边界，不再重复 pickle、CSV 或基础文件语法。

第 13～18 章补上读框架代码需要的语言能力：类型、数据模型、协议与泛型、装饰器、生成器和资源协议。这里要分别理解静态类型提示和运行时输入验证；Python 默认不强制执行函数与变量注解，Pydantic 承担的是另一层职责。[Python typing 文档](https://docs.python.org/3/library/typing.html)、[Pydantic 模型文档](https://docs.pydantic.dev/latest/concepts/models/)

第 19～24 章是整条路线的重点。先解释 coroutine 和调度，再学习 Task，然后单独处理取消与超时，之后进入 TaskGroup、并发控制和异步流。把取消放在 TaskGroup 前面，是因为任务组的失败处理本身就涉及取消兄弟任务和等待清理；不能只学会一个 async with 写法。[Python 3.14 coroutine 与 Task 文档](https://docs.python.org/3/library/asyncio-task.html)

第 25～28 章把这些机制应用到 HTTP、数据库、上下文、测试和 Web 服务。HTTPX 客户端复用与流关闭、FastAPI 应用生命周期都涉及资源所有权，因此安排在异步资源章节之后。[HTTPX 异步客户端文档](https://www.python-httpx.org/async/)、[FastAPI lifespan 文档](https://fastapi.tiangolo.com/advanced/events/)

第 29 章用小型运行器串起已学知识，第 30 章迁移到真实框架并阅读实际调用链。未指定框架时暂定 PydanticAI，主要为了衔接类型模型、函数工具与异步运行；其测试模型与 MCP 客户端文档也提供了本地验证的切入点。开始第 30 章时仍需核对当时版本与兼容性，也可直接替换为你选定的框架。[PydanticAI 测试文档](https://ai.pydantic.dev/testing/)、[MCP 客户端文档](https://modelcontextprotocol.io/docs/develop/build-client)

## 学习顺序与投入重点

默认按 11 → 30 学习，有以下调整空间：

- **第 11～12 章可以快速过。** 如果已经能解释解释器与 pip 的对应关系，能重建依赖环境，并区分传输、HTTP、JSON 与业务错误，可直接做验收练习。
- **第 13～18 章按需补深度。** 类型、数据模型和装饰器应掌握；第 15 章泛型的复杂变型推导只作选学。第 17～18 章用于支撑后续异步流与会话清理。
- **第 19～24 章建议连续学习。** 不把 coroutine、Task、TaskGroup 压缩为同义词，也不跳过取消与失败路径实验。
- **第 25～27 章用于检验能否写可靠 I/O 代码。** 真实传输和可控替身分开验证；测试尤其关注取消、并发上限与资源释放。
- **第 28 章可在需要服务化时学习。** 若想先进入框架，可从第 27 章进入第 29～30 章，再回来做 FastAPI。
- **第 29～30 章逐步组合。** 第 29 章关注运行机制，第 30 章关注真实框架接管了什么，以及 MCP 会话如何创建与关闭。

20 个部分不是固定 20 天。一次对话可以生成一个完整章节；学习时可以只完成一个实验再继续。第 25、29、30 章包含多个递进步骤，适合分多轮阅读和练习。

## 每份 Prompt 为什么不只是知识点清单

每份文件同时提供：

- 已会什么、还不应假定会什么，以及与前章的关系。
- 本章要解决的实际问题和必须解释的运行行为。
- 最小实验、Agent 场景、常见错误与可观察证据。
- 明确的章节边界，防止一个问题扩展成整套框架。
- 具体输出目录、运行要求、练习和验收标准。

没有额外的历史 context 也可以开课：prompt 已经把“学习问题”组织成了输入材料。后续模型仍需读取项目文件与对应官方资料，不能把 prompt 中的知识点名称当成已经完成的讲解或验证。

## 贯穿路线的业务场景

统一使用一个小型“文档与记录查询助手”，逐步引入：

1. 本地文档检索 `search_docs`。
2. 本地 HTTP 状态查询 `fetch_status`。
3. 临时 SQLite 记录查询 `lookup_record`。
4. 可控 FakeLLM 返回工具请求与最终回答。
5. 最后一章用真实框架和一个真实本地 MCP 服务接入这些工具。

不同章节可以用更小的独立样例解释单条规则，不必强行引用前章内部代码。所有基础实验默认不需要付费服务或真实 API Key。FakeLLM 用于验证调用链，不能据此声称验证了真实模型推理；普通函数替身也不能冒充 MCP 协议集成。

## 仓库约定与版本

规划依据是当前仓库实际文件：`pyproject.toml` 要求 Python >= 3.14，Pyright 与 Ruff 目标版本为 3.14，本机项目解释器验证为 3.14.7。未来生成章节时应重新核对，而不是把规划时版本当成永远不变。

现有 `java_to_python/run_all.py` 只登记第 1～10 章，而且假设每节有 Java 程序。新增课程先提供各章独立 Python 运行命令；这份规划没有把未来章节提前接入现有运行器，也没有改动现有课程与依赖环境。后续若要统一执行全部课程，应单独适配纯 Python 章节和可选第三方依赖。

依赖学习先分清 venv/pip，再引入 uv 的声明、锁定与同步工作流。进入后续章节时沿用当时已选定的项目方式，不为每个包重新设计一套管理规则。[uv 项目文档](https://docs.astral.sh/uv/guides/projects/)

这些文件是未来对话的用户 prompt，供主动复制使用；它们不是自动适用于整个仓库的 AGENTS.md 或 skill 修改。
